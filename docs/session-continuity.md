# User requests after interrupted tasks (#39)

A task can fail without disabling its conversation. This follows #28's cancellation, publication fencing and no-automatic-replay policy. It separates **execution admission** from **uncertainty about previous effects**.

## Runtime behavior

- A normal user-authored request, including “continue the previous task”, can run in the same session after the interrupted handler has settled and its managed execution has stopped. No `/reconcile` acknowledgment is required on this path. This is a new request with a new turn ID/generation; the original prompt is never automatically resubmitted.
- On timeout, revoke the previous turn's publication/store authority and propagate abort immediately. Requests arriving during cleanup remain in the existing per-session queue. Each request's dispatch timeout starts when its own handler starts, excluding queue wait.
- The gateway launches the CLI in an owned POSIX process group and holds its actual ChildProcess/PID. A per-attempt local socket carries stdin/stdout/stderr between the SDK proxy and gateway. The gateway independently observes child closure and checks running group members with absolute `/bin/ps`, terminating/escalating interrupted work as necessary. Files, nonce-bearing status messages, SDK errors, sent signals and promise settlement never prove teardown. Socket credentials are stripped from the CLI/tool environment, but their secrecy from same-user processes is not an admission assumption.
- If the gateway's own OS spawn emits an error without ever acquiring a PID, its subsequent close is authoritative non-start evidence for that managed attempt. Admission can reopen once the handler settles; no process-group scan is possible or needed for that rejected child. A proxy exit alone, a missing handshake/PID without the gateway error, or an error after a PID was acquired is insufficient. This evidence is used for admission only: it does not replay the failed request or change the bridge's existing conservative retry-risk classification.
- The router waits up to three seconds for cleanup before returning control to the queue. If the handler is still alive or proof is unavailable, requests fail visibly rather than overlap the same work environment. A handler that subsequently settles with successful teardown proof releases admission automatically. A subsequent request also rechecks delayed kernel-observed closure from a settled handler before deciding whether maintenance is needed. Unobservable, historical and crash-interrupted executions keep the owner maintenance path. Windows currently keeps this conservative fallback because no equivalent gateway-owned Windows Job Object is implemented.
- Successful normal execution keeps its existing semantics, including intentionally started external/background services. Stopped interrupted execution may already have changed files or external systems. Neither admission reopening nor a stopped-process check asserts external rollback, exactly-once execution or termination of detached/remote work that escaped the owned process group.

Shutdown disposes and clears retained scopes from settled quarantined turns, including failed handshakes, closing their socket listeners and removing temporary control directories. Cleanup finishing after shutdown also disposes unconfirmed scopes without writing through a possibly closed ledger. Resource disposal never changes durable quarantine or stands in for stopped-execution proof.

## Continuation and history

`interrupted_turns` records task ID, failure/cancellation/timeout reason, stage and execution risk, independently from the session's current execution row. It contains no raw prompt, tool output, SDK exception text, credentials or arbitrary error payload. A subsequent request receives the latest pending closed snapshot alongside the existing sender/security frame and SDK thread mapping. The frame instructs the agent to follow the current request only, inspect actual work before continuing, and verify uncertain operations before repeating them. This instruction assists continuation; it is not an enforceable idempotency boundary for arbitrary tools.

The snapshot is consumed only after a following model turn that received it successfully commits a nonempty response. `/help`, `/config`, `/reset` and other pre-model returns preserve the pending snapshot, without deleting the audit record or marking external effects reconciled. Reset does not erase this interruption metadata. Consumed snapshots use seven-day retention; pending context survives until presented successfully. Historical/crash quarantine is not silently migrated into a stopped execution.

If a thread is invalid or encrypted content cannot be resumed, this change does not add an automatic fresh-thread replay. The error remains explicit. A future thread repair can carry verified history but must not resubmit an already-started request without evidence.

## Tests and boundaries

Coverage includes failed/timeout turns followed by unrelated requests or explicit continuation, queued cleanup, positive non-execution, missing/failed proof, persistent metadata, generation fencing, real SDK failure and resume framing, and an owned subprocess tree whose child ignores SIGTERM. Production socket/gateway/router/handler wiring checks that the next request invokes the model once, carries the interruption snapshot, and delivers its response.

The tests use synthetic local processes and transport fixtures; no production credentials, provider fault injection or live external-effect reconciliation are used. Operator `/reconcile` remains available when cleanup cannot be confirmed. The previous recovery guide describes that maintenance interface.

## RC correction

The initial status-file acknowledgment was forgeable, including by an ordinary owned group member that learned its proxy parent's environment. It is removed as an authority source. Managed POSIX execution is now launched by the gateway itself; only its own process handle and process-group inspection decide reopening. The SDK proxy is a transport and may exit promptly on cancellation/backpressure while the gateway continues teardown independently. A supported proxy is required to establish this ownership; direct launch, unavailable proxy and Windows do not receive scope credentials and remain maintenance cases. Normal successful CLI exit preserves intentional background services; interrupted execution (even a CLI that exited zero) must still clear the tracked group before admission. This is a lifecycle boundary, not OS-user isolation: the gateway code/memory and kernel process API are trusted, and detached/remote effects remain outside the group.

Regression coverage includes correct-nonce file and socket forgery with a ready SIGTERM-resistant descendant still writing; a direct fallback with a matching forged file; gateway cleanup under stdout backpressure; Unicode transport; preservation of normal background work; and failure → each slash command → next model request context delivery/consumption. CI strictly compiles every TypeScript test changed by this PR.

This main integration combines #28/#30 with #37/#40 and retains main's exact registration-owner reconciliation gate, hashed audits, aggregate quarantine limits, final-output selection and durable evidence retention. No scoped alias is inferred from incoming UID suffixes. The admission gate and optional private diagnostics have separate roles; permitting a new request after gateway-observed cleanup does not authorize replay of the old request. Validation for this integrated source is recorded in the integration PR. Native Windows, live provider/backend faults and external effects remain outside local validation.

## Gateway launch rejection and shutdown follow-up

Regression coverage now includes real OS `ENOENT` and `EACCES` at the gateway launch boundary, through the real SDK, proxy, bridge, router and SQLite store. It verifies no PID or managed CLI execution, a single gateway attempt, a clean admission row and one subsequent user-handler call without replay. A separate real-child control injects an error after PID acquisition while an owned descendant remains alive, ensuring the error cannot bypass group inspection. Shutdown coverage checks listener/directory removal for a failed handshake, durable quarantine across SQLite reopen, idempotent repeated shutdown, and handler/cleanup completion after the ledger is closed.
